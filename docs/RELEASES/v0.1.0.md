## Goal

The application runs in Docker on the owner's laptop, survives restarts, rebuilds and
reboots, reports its own health, and can migrate its own schema. There is one way to run
it, and the owner never needs a second command.

This release deliberately contains no features. It contains the ground the other eleven
releases stand on, and getting it wrong would be discovered expensively later.

## In scope

**Container and compose.**
Multi-stage `Dockerfile` (Node 22 alpine base, pinned by digest). `docker-compose.yml` with
one service `pdm` now and `pdm-mcp` added in 0.10.0. `restart: unless-stopped`, health
check, no capabilities, no privileged mode, no host network. Volumes `./data:/data` and
`./backups:/backups`. Ports `127.0.0.1:${PDM_PORT:-8080}:${PDM_INTERNAL_PORT:-8080}`.
Environment: `TZ`, `PDM_DATA_DIR`, `PDM_BACKUP_DIR`, `PDM_BACKUP_COUNT`, `NODE_ENV`.
A non-root user (`pdm`, uid 10001) owns the mounted folders.

**Configuration.** Every value comes from the environment with a working default, so the
app runs with no `.env` at all. `.env.example` documents each one. Configuration is read
once at boot through a single zod-validated object; an invalid value fails the boot with a
clear message naming the variable, rather than starting in a broken state.

**Database and migrations.** `better-sqlite3` with `journal_mode=WAL`,
`foreign_keys=ON`, `busy_timeout=5000`, `synchronous=NORMAL`. The migration runner:

- keeps an ordered `schema_migrations` table
- takes a backup before each migration, using the online API, into
  `./backups/migrations/` (`DEP-09`, [ADR 0007](../adr/0007-backup-export-import.md))
- runs inside a transaction
- on failure, rolls back, restores the backup and aborts the boot with the restore path in
  the message
- is idempotent: an already-applied migration is skipped
- exposes a `migrate:status` command for the CLI

**Schema for this release:** `schema_migrations` and `settings` only. The `settings` table
(`key TEXT PRIMARY KEY`, `value TEXT`, `updated_at INTEGER`) is created now with its
defaults, because every later release reads settings and the settings screen should not
need a migration of its own.

**HTTP surface.**
`GET /health` returning `{status, db, version, uptime_s, migrations, time_zone}` and 503
when the database is unreachable (`DEP-06`). A static file server for the built frontend
with an SPA fallback to `index.html` for client-side routes. A JSON error envelope used by
every later route. A request id in a response header.

**Frontend shell.** Layout with a left navigation (Today, Tasks, Projects, Calendar, Day
log, Reminders, Reports, Library, Settings), a top bar placeholder, routing, light and dark
themes following the OS preference (`UI-09`), an error boundary, a 404 page, and a
loading state convention. Navigation items for unbuilt features are present but disabled
with a tooltip naming the release that adds them, so the shell is honest about what exists.

**Tooling.** TypeScript strict mode in all workspaces, ESLint with typescript-eslint and
Prettier, Vitest with a fast watch mode, a `pnpm`-style script set documented in
`AGENTS.md`, a GitHub Actions workflow running lint, typecheck, test, build, and
`docker compose config` plus an image build, and a pinned lockfile committed.

**Documentation.** `README.md` with start, stop, restart, logs, backup, restore, upgrade
and removal (`NFR-MAINT-03`, `DEP-11`); a note to start Docker Desktop at login to
mitigate `R1`.

## Design notes

**The bind address is `0.0.0.0` inside the container, on purpose.** Docker's published
port is the network boundary ([ADR 0001](../adr/0001-stack-and-deployment.md), S1 in the
roadmap). A comment in the server bootstrap says so, and an integration test connects to
the app from a second container to prove the MCP server's future access path works.

**`nowMs()` is the only clock.** Introduced here, used everywhere from 0.2.0 onward
([ADR 0004](../adr/0004-time-and-duration-model.md)). No other file calls `Date.now()`.
This is what makes the timer and reminder tests deterministic.

**Timestamps are epoch milliseconds** from this release onward, so no migration has to
convert a string column later.

**Settings defaults are written on first boot**, not read lazily with fallbacks scattered
through the code. One code path reads settings; there is no other.

**Migration files are plain SQL**, named `NNNN_name.sql`, applied in numeric order, each
wrapped in a transaction. No migration framework DSL, because `NFR-MAINT-02` wants
migrations to be auditable by a human.

**The health check is meaningful.** It opens the database and runs `SELECT 1` plus a
migration-count check, so a container that is up but broken does not report healthy.

**SPA fallback excludes asset paths**, so a missing JavaScript bundle returns 404 rather
than being masked as `index.html`.

## Acceptance criteria

1. Given a clean clone, when `docker compose up -d` runs, then the container reaches
   healthy status within 30 seconds and nothing is installed on the host. (`DEP-01`)
2. `GET /health` returns HTTP 200 with `{status:"ok", db:"ok", version:"0.1.0", …}`; with
   the data folder made unwritable it returns HTTP 503 with `db:"error"` and the process
   logs the reason. (`DEP-06`)
3. A file written into `./data` still exists after `docker compose down && docker compose
   up -d`, and after rebuilding the image from scratch and recreating the container.
   (`DEP-03`)
4. `docker compose down` leaves `./data` intact, so `up` again returns the same state;
   `docker compose down -v` plus deleting `./data` removes everything. (`DEP-11`)
5. Migrations run automatically at start, in order, and re-running them changes nothing. A
   migration that fails rolls back, restores the pre-migration backup, aborts the boot and
   names the backup file in the error. (`DEP-09`)
6. Setting `PDM_PORT=9090` in `.env` starts the app on 9090, so a clash with another local
   service is avoided. (`DEP-02`, `R5`)
7. From another device on the same LAN the app is not reachable; from the host,
   `127.0.0.1:${PDM_PORT}` works. (`NFR-SEC-01`)
8. `docker compose restart` returns the app to the same state, and the container has
   `restart: unless-stopped` so it returns after a reboot. (`DEP-04`)
9. `docker compose exec pdm id -u` prints a non-zero uid, and the process has no extra
   capabilities. (`DEP-10`, `NFR-SEC-04`)
10. The container is a single application container with only `/data` and `/backups`
    mounted. No other host path, no host network. (`NFR-SEC-04`)
11. `TZ=Asia/Kolkata` is honoured: `/health` reports that zone and the shell renders times
    in it. (`DEP-05`, `NFR-TIME-01`)
12. The frontend shell renders, both themes follow the OS preference, unknown routes show
    a 404 page, and a thrown error shows the error boundary rather than a blank screen.
    (`UI-09`)
13. The navigation shows only 0.1.0 destinations enabled; the rest are visibly disabled
    with the release that adds them.
14. `pnpm lint`, `pnpm typecheck`, `pnpm test` and `pnpm build` all pass from a clean
    install.
15. The CI workflow is green on the default branch.
16. `README.md` documents install, start, stop, restart, logs, backup, restore, upgrade
    and removal, and mentions starting Docker at login. (`NFR-MAINT-03`)
17. The database file is a plain SQLite file, readable with any SQLite client.
    (`NFR-DATA-01`)

## Exit test

The owner runs this. About ten minutes. Any failure blocks 0.2.0.

| # | Do this | Expect |
| --- | --- | --- |
| 1 | Copy `.env.example` to `.env`, change `PDM_PORT` to `9090` | — |
| 2 | `docker compose up -d` | Container healthy within 30 seconds |
| 3 | `docker compose ps` | One service, `running (healthy)`, port `127.0.0.1:9090→8080` |
| 4 | Open `http://127.0.0.1:9090` | The app shell loads, navigation visible, rest greyed out |
| 5 | Open `http://127.0.0.1:9090/health` | 200, `status:"ok"`, `db:"ok"`, `version:"0.1.0"`, your time zone |
| 6 | Switch macOS or Windows to dark mode, reload | The app follows it |
| 7 | `docker compose exec pdm id -u` | A non-zero number |
| 8 | `echo test > ./data/probe.txt` | File created on the host |
| 9 | `docker compose down` then `docker compose up -d` | Healthy again; `./data/probe.txt` still exists |
| 10 | `docker compose down -v`, `rm -rf ./data`, `docker compose up -d` | Healthy again; a fresh empty database |
| 11 | From a phone on the same Wi-Fi, open `http://<laptop-lan-ip>:9090` | Connection refused or timeout |
| 12 | `docker compose logs -f pdm` | No errors or warnings; Ctrl+C to exit |
| 13 | Read `README.md` | Start, stop, logs, backup, restore, upgrade and removal are all documented |

## Risks

| Risk | Mitigation |
| --- | --- |
| `R1` — Docker Desktop not running after reboot | `restart: unless-stopped` handles the container; the README tells the user to start Docker at login |
| The volume is owned by root on Linux, so the non-root user cannot write | The image creates uid 10001; the README documents the one `sudo chown` needed on a fresh Linux host |
| `better-sqlite3` needs a native build, which breaks when the Node version moves | Base image pinned, prebuilt binaries used, an image build in CI so a break is caught on the PR |
| Bind address confusion leads someone to "fix" it to `127.0.0.1` and break future MCP access | One constant with an explanatory comment, plus the second-container integration test |
