## Goal

The whole schema exists, nothing can be deleted, and projects, tasks and tags are
usable.

This release has no timer and no closure gate. It has the ground they stand on:
fifteen tables, the constraints that make them trustworthy, and the first real
service functions. A schema mistake here is discovered by every later release, and
a schema change later is a migration against real data, so this is the cheapest
moment in the whole ladder to get the shape right — which is exactly why the full
model lands here rather than incrementally.

## In scope

- All 15 entities of SRS §9.1, with `uid`, `archived_at`, `created_at`, `updated_at`
- Migrations for the schema, the views, the triggers and the indexes
- `BEFORE DELETE` triggers on the 13 user-data tables (`DATA-10`)
- `CREATE UNIQUE INDEX … WHERE ended_at IS NULL` on `time_entries` (`DATA-02`)
- `BEFORE INSERT` trigger capping `task_links` at 3 per task (`DATA-01`, `BR-04`)
- `closure_records` check constraint: `result = 'not_fulfilled'` requires a
  non-empty `lagging_reason` (`DATA-03`)
- `activity_log` written by the service layer on every change (`FR-STAT-05`)
- Project CRUD with archive and restore (`FR-PRJ-01`…`04`)
- Task CRUD with links, score, estimate, dates, status, todos, acceptance criteria
  and reference materials (`FR-TASK-01`…`09`, `FR-TODO-01/02`, `FR-AC-01/02`,
  `FR-REF-01/02`, `FR-TAG-01/02/05`)
- Task list with sort and filter (`FR-VIEW-01`, `FR-VIEW-03`)
- "Show archived" and Restore everywhere, with no Delete button anywhere
  (`UI-04`, `UI-17`, `DATA-11`)
- Form validation that preserves the typed value (`UI-08`)
- Capability classification on every route, so `MCP-14` has something to read
- Web UI for the above

## Out of scope

Timer, Day log, closure gate, calendar, reminders, search, reports, MCP. Time
entries exist as a table because the schema is written once; nothing writes one
until 0.3.0.

## Out-of-scope by decision

- **`drizzle-orm` stays unused.** It is declared in `apps/api/package.json` and has
  no ADR. 0.1.0 shipped with that as a recorded exception, and this release is not
  the place to either wire it up or remove it. The first query that would use it is
  the project list in this release, so the honest options are to write that query
  with it (and write the ADR) or to drop the dependency. **This spec does not
  decide.** It goes to `BACKLOG.md` as a question for the owner, because choosing
  silently is how it survived 0.1.0.
- **No search.** `reference_materials` is a plain table here. FTS5 indexing is
  0.8.0 and gets its own migration, per ADR 0005.

## Acceptance criteria

1. Adding a 4th link to a task returns 422 with a clear message, and a direct SQL
   insert of a 4th link is rejected by a database trigger (`DATA-01`, `US-06`).
2. Every one of the 13 user-data tables refuses `DELETE` at the database level,
   proven by a test that enumerates all of them and asserts on the count (`DATA-10`).
3. Archiving a project hides it and its tasks from pickers and default lists, keeps
   all data, and restoring brings everything back (`FR-PRJ-04`, `BR-16`, `US-07`).
4. Archiving a tag hides it from pickers but leaves existing entries and per-tag
   totals unchanged (`FR-TAG-05`).
5. Archiving a todo keeps its time entries linked to it — asserted here against the
   foreign key and the `archived_at` flag, and verified with real entries in 0.3.0
   (`DATA-05`, `FR-PHASE-05`).
6. Editing an Ended task is allowed and the change is recorded in history
   (`FR-TASK-12`, `FR-STAT-05`).
7. No API route accepts a delete of user data; a test scans the route table and
   fails on any `DELETE` method (`DATA-09`).
8. A task may belong to no project and shows in a virtual "No project" bucket
   (`FR-PRJ-02`).
9. Validation errors name the field and the typed value is preserved (`UI-08`).
10. Archived items appear in search-independent lists only when "Show archived" is
    on (`DATA-11`).
11. Every one of the 15 tables carries a unique `uid`, and no table is missing
    `archived_at` except the 5 system tables that are exempt (`DATA-13`).
12. A route with no declared capability is refused, and a principal without the
    capability gets 403 — asserted through `app.inject()` with a principal that has
    no capabilities at all (`MCP-14`).
13. The activity log records every status change with a before and after value
    (`FR-STAT-05`).
14. `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm test:int` and `pnpm build`
    pass from a clean checkout, on a database created by the migrations alone.

## Exit test (owner, ~15 minutes)

1. `docker compose up -d --build` and confirm the app is healthy.
2. Create a project. Create three tasks in it, and one with no project.
3. Give a task three links. Try a fourth: it is refused with a message naming the
   limit.
4. Add a todo, two acceptance criteria and a reference material to one task.
5. Create two tags, apply one to a task's tags.
6. Archive the project. Its tasks vanish from the default list; "Show archived"
   brings them back; Restore brings the project back.
7. Archive a tag. It disappears from the picker.
8. Change a task's status twice and open its history. Both changes are there, with
   before and after.
9. Search the whole app for a Delete button. There is none.
10. `docker compose logs pdm-migrate` shows the schema migrations applied in order.

## Risks

**Schema churn is cheapest now.** Every table created here is a table every later
release queries, and the alternative — adding `uid` and `archived_at` in a later
release — means touching every table, every export and every import at once
(ADR 0007). This is the release where a wrong column name is a rename rather than
a migration against real data.

**The 13 no-delete triggers can disagree with the application.** If a service
archives and a trigger also fires on delete, the two must not contradict each
other. The triggers are the last line of defence, not the mechanism, and the
enumeration test is what keeps the count honest.

**`FR-STAT-01` is a design constraint, not a test.** A task must never reach
`ended` by any route. That is only provable if exactly one function can set it, so
`ended` is not writable from a generic update path in this release even though
nothing can legitimately set it until 0.5.0.
